L187: # Daeva
L188: 
L189: Open-source AION 2 build and meta analyzer that studies leaderboard data to identify popular skills, stigmas, equipment patterns, and other build trends.
L190: 
L191: > Beta
L192: >
L193: > Daeva is currently in beta. The core analyzer and fallback systems are production-deployed, but the upstream AION 2 leaderboard API is currently unavailable, preventing full live-data validation.
L194: >
L195: > See the cite84†Changelog for recent updates.
L196: ## What Daeva Does
L197: 
L198: Daeva helps you understand the meta by analyzing high-ranking players across all leaderboards. It provides data-driven recommendations on:
L199: 
L200:   * Top active and passive skills
L201:   * Must-have stigma combinations
L202:   * Popular equipment and substats
L203:   * Arcana choices and synergy patterns
L204:   * Quick Build analysis for current trends
L205: By aggregating configurations from the official APIs and community platforms, Daeva reports observed build trends rather than claiming to mathematically determine the "perfect" build.
L206: ## How It Works
L207: 
L208: Daeva uses a resilient scraping and aggregation architecture:
L209: 
L210: `Leaderboard Provider` → `Player Build Fetch` → `Aggregation` → `Analyzer`
L211: 
L212: Because upstream APIs can be unreliable, Daeva follows a resilience ladder to ensure you always have access to data:
L213:   1. Official: Live data directly from the official AION 2 API.
L214:   2. Shugo Fallback: Alternative provider if official APIs are constrained.
L215:   3. Full-Build D1 Cache: Cloudflare D1 cache serving instantly from background prefetch.
L216:   4. Historical Meta Snapshot: Stored aggregate snapshot if all live data is unavailable.
L217:   5. Explicit Unavailable State: If there's truly no data, Daeva tells you, rather than fabricating player builds.
L218: ## Data Freshness
L219: 
L220: The UI clearly indicates the health of the data source you are viewing:
L221: 
L222:   * Live Data: Full live synchronization.
L223:   * Partial Data: Live synchronization with some servers failing.
L224:   * Cached Data: Cache under 2 days old.
L225:   * Stale Cache: Cache 2–7 days old.
L226:   * Historical Snapshot: Cached aggregate data >7 days old, used as an ultimate fallback.

L228: ## Local Development Setup
L229: ### Prerequisites
L230: 
L231:   * cite100†Node.js†nodejs.org v25+
L232:   * A cite101†Cloudflare†cloudflare.com account (for D1 and Pages)
L233:   * cite102†Wrangler CLI†developers.cloudflare.com L234: 
L235: ### 1. Install dependencies
L236: 
L237:     npm install
L238: ### 2. Database Setup
L239: 
L240: The app uses a Cloudflare D1 database (`player-cache`) for caching player equipment. To set up the local SQLite database, run this once:
L241: 
L242:     npx wrangler d1 execute player-cache --local --command="CREATE TABLE IF NOT EXISTS player_cache (character_id TEXT NOT NULL, server_id TEXT NOT NULL, region TEXT, equip_data TEXT NOT NULL, equip_details TEXT NOT NULL, fetched_at INTEGER NOT NULL, PRIMARY KEY (character_id, server_id))"
L243: ### 3. Environment Variables
L244: 
L245: Create `.env.local` for the Next.js app and `.dev.vars` for the Wrangler local environment. Use these placeholders (do not commit real secrets):
L246: 
L247:     # .dev.vars / .env.local
L248:     ADMIN_SECRET=your-secret-here
L249:     API_URL=http://localhost:3000
L250: 
L251: Note: `CLOUDFLARE_API_TOKEN` is used exclusively for CI/CD deployment via GitHub Actions. Never commit it.
L252: 
L253: ### 4. Start the development server
L254: 
L255:     npm run dev
L256: 
L257: Open cite103†http://localhost:3000†localhost in your browser.
L258: ## Background Prefetching
L259: 
L260: Daeva includes a background prefetch system that runs entirely in-process on the Node.js server. On startup, it warms the cache by fetching the top 100 players for every class and leaderboard.
L261: This is governed by a scheduled workflow that calls the `POST /api/prefetch/run` endpoint (authenticated via `ADMIN_SECRET`) every 30 minutes, storing results in the D1 cache. This ensures instant load times for users. During upstream outages, Daeva gracefully falls back to the latest cached data.
